# ArchSwift

**ArchSwift** — открытый графический мастер установки локальных пакетов
Arch Linux (`*.pkg.tar.zst`). Двойной щелчок по пакету открывает привычный
пошаговый мастер в стиле установщиков Windows:

1. **Приветствие** — имя, версия, архитектура, зависимости, размер, подпись и
   другие сведения из `.PKGINFO`.
2. **Установка** — нативный диалог Polkit (KDE Auth / GNOME Polkit), затем
   `pkexec pacman -U --noconfirm <package>` в отдельном потоке. Интерфейс не
   зависает, журнал pacman обновляется в реальном времени.
3. **Завершение** — успех с кнопкой «Готово» либо понятная ошибка с последними
   строками журнала и кнопкой «Повторить».

Приложение написано на Rust с GTK4 и рассчитано на Arch Linux и производные
дистрибутивы с pacman и Polkit.

Репозиторий: <https://github.com/watsbunny/ArchSwift>.

## Возможности

- Безопасный разбор архива без распаковки всей полезной нагрузки.
- Запуск внешней команды без shell: путь к пакету не может стать командой.
- Отдельные потоки для чтения метаданных и установки, обмен с GTK через канал.
- Три языка интерфейса: английский, русский, беларуский. Язык выбирается
  автоматически по локали пользователя.
- Собственный MIME-тип `application/x-arch-swift-package`, чтобы пакет не
  открывался архиватором.
- Иконки, `.desktop`-файл и скриптлеты pacman, обновляющие кэши MIME, desktop
  и hicolor-иконок сразу после установки.
- Защита от закрытия окна во время работы pacman.

## Структура проекта

```
.
├── Cargo.toml                     # зависимости и профиль release
├── Cargo.lock                     # воспроизводимая сборка
├── build.rs                       # GResource с иконками и реестр переводов
├── src/
│   ├── main.rs                    # точка входа, Application ID, канал сообщений
│   ├── ui.rs                      # трёхшаговый мастер GTK4
│   ├── metadata.rs                # безопасное чтение .PKGINFO из архива
│   ├── installer.rs               # pkexec + pacman в отдельном потоке
│   └── i18n.rs                    # загрузка и выбор TOML-переводов
├── localization/lang/             # en.toml, ru.toml, be.toml
├── assets/
│   ├── icons/                     # SVG-иконки приложения и типа файла
│   └── resources.gresource.xml    # упаковка иконок в GResource
├── arch-swift.xml                 # MIME-тип application/x-arch-swift-package
├── arch-swift.desktop             # ярлык и ассоциация с MIME-типом
├── arch-swift.install             # post_install/post_upgrade/post_remove
└── PKGBUILD                       # сборка AUR-пакета
```

## Зависимости

Для сборки:

- Rust 1.80+ и Cargo;
- GTK4 с заголовочными файлами (`gtk4`);
- `glib-compile-resources` из пакета `glib2` (нужен `build.rs`);
- `pkg-config`, `xz` (для сборки крейта `xz2`);
- базовые инструменты `base-devel`.

Для работы:

- `gtk4`, `polkit`, `pacman`;
- агент Polkit рабочего стола (KDE Polkit Auth Agent, GNOME Shell Polkit);
- `shared-mime-info`, `desktop-file-utils`, `hicolor-icon-theme` — для
  корректной интеграции с рабочим столом.

## Сборка и запуск без установки

```bash
cargo build --release
./target/release/arch-swift ./example-1.0-1-x86_64.pkg.tar.zst
```

Без аргумента мастер предложит выбрать пакет через диалог GTK.

Проверка тестов (включая контроль одинакового набора ключей во всех языках):

```bash
cargo test
```

## Установка через PKGBUILD

Так как `PKGBUILD` лежит рядом с каталогом исходников `src/`, запускайте
`makepkg` с отдельным `BUILDDIR`. Иначе makepkg использует `./src` как каталог
распаковки и может удалить исходники Rust:

```bash
BUILDDIR=/tmp/arch-swift-build makepkg -si
```

В отдельном AUR-клоне (где нет каталога `src/`) достаточно обычного
`makepkg -si`.

Если раньше был установлен пакет `arch-linux-witchery` (прежнее имя проекта),
удалите его перед установкой: `sudo pacman -Rns arch-linux-witchery`. Имя
пакета, MIME-тип и App ID изменились, поэтому старая и новая версии не
заменяют друг друга автоматически.

Перед публикацией релиза замените `source` и `sha256sums` в `PKGBUILD` на
реальный архив/тег вашего репозитория и выполните `updpkgsums`. В текущем виде
`source` указывает на GitHub-релиз проекта, а сумма помечена как `SKIP`, чтобы
шаблон не ломался до публикации первого тега.

После установки пакета:

```bash
xdg-mime query default application/x-arch-swift-package
# arch-swift.desktop
```

Если ассоциация не применилась в уже открытом сеансе KDE/GNOME, задайте её
вручную:

```bash
xdg-mime default arch-swift.desktop application/x-arch-swift-package
update-desktop-database ~/.local/share/applications 2>/dev/null || true
```

Скриптлеты пакета автоматически вызывают `update-mime-database`,
`update-desktop-database` и `gtk-update-icon-cache` (или
`gtk4-update-icon-cache`) при установке, обновлении и удалении.

## Локализация

Все пользовательские строки находятся в `localization/lang/*.toml`. `build.rs`
сканирует каталог перед сборкой, генерирует реестр языков `CATALOGS` и
встраивает содержимое файлов в бинарник через `include_str!`. Во время работы
файлы перевода не читаются, поэтому приложение остаётся самодостаточным.

Приоритет выбора языка:

1. `ARCHSWIFT_LANG` (удобно для тестирования: `ARCHSWIFT_LANG=be`; неизвестный
   код даёт английский и не зависит от системной локали);
2. `LANGUAGE` (список через двоеточие);
3. `LC_ALL`, `LC_MESSAGES`, `LANG`;
4. английский язык как fallback.

Поддерживаются коды `en`, `ru`, `be`; локаль вида `be_BY.UTF-8` определяется
корректно. Если в переводе отсутствует ключ, используется английский текст, а
при отсутствии и там — сам ключ. Тест `all_catalogs_have_the_same_keys`
не позволяет забыть перевод при добавлении новой строки.

### Добавление языка

1. Создайте `localization/lang/<code>.toml` на основе `en.toml`.
2. Запустите `cargo test` — тест проверит полноту набора ключей.

`build.rs` сам находит все `*.toml` в `localization/lang` и встраивает их в
бинарник, а `match_locale` автоматически распознаёт новый код. Правки в
Rust-коде не нужны. Если для языка нужен региональный вариант, назовите файл
`<code>-<REGION>.toml` (например, `pt-BR.toml`): он будет выбран для
соответствующей локали, а базовый `<code>.toml` останется запасным.

## Модель безопасности

- Метаданные читаются без root-прав; путь канонизируется, проверяется тип файла
  и расширение.
- `pkexec` запускается через `std::process::Command` с массивом аргументов,
  без `sh -c`, поэтому имена файлов не интерпретируются оболочкой.
- Пароль администратора вводится только в системном агенте Polkit; приложение
  его не читает и не хранит.
- Используется `--disable-internal-agent`, чтобы не допустить текстовый fallback
  pkexec в графическом сеансе.
- Мастер предупреждает, что install-скрипты пакета выполняются от имени root.
- Пакеты без `.sig` не проверяются автоматически; это явно отображается в
  карточке пакета.
